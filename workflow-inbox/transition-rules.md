# 실험 작업 전환 지침

담당자는 매번 작업 ID, 최신 상태·버전, 열린 질문과 사용자 결정을 읽는다. 사용자의 명시적 요청 또는 승인된 실험 범위의 에이전트 판단으로, 아래 조건을 만족할 때 한 단계 전환한다. 요청과 근거가 충돌하면 현재 상태를 유지하고 빠진 조건을 기록한다.

| 현재 → 다음 | 판단 기준 |
|---|---|
| 신규 → 계획중 | 작업 ID와 목표를 정했다. |
| 계획중 → 개발대기 | 범위와 인수조건을 기록해 개발자가 검토할 수 있다. 미결 사항을 명시한다. |
| 개발대기 → 계획수정 | 구현 결과를 결정할 질문이 남았다. 질문을 해당 작업의 `decision.md`에 남긴다. |
| 계획수정 → 계획중 | 사용자 답변이나 변경 결정을 `decision.md`에 기록하고 기획 보완을 시작한다. |
| 개발대기 → 개발중 | 인수조건을 검토했고 착수 권한이 있다. |
| 개발중 → 개발완료 | 산출물이 있고 인수조건을 실제 검증한 결과가 있다. |

프로젝트 루트에서 `python3 bin/workflow ID 현재버전 다음상태 근거`로 기록한다. 근거에 판단 주체와 요청·결정·검증 결과의 위치를 포함한다. 버전 충돌 시 다시 읽고 판단한다. 정의되지 않은 전환은 수행하지 않는다. 로컬 완료와 외부 티켓 완료는 별도다.

채팅 이동과 상태 전환은 별개다. 같은 채팅 또는 하위 위임이면 담당을 유지한다. 새 개발 채팅으로 책임까지 넘기면 생성이 확인된 채팅 ID를 담당으로 기록하고 기획 채팅 링크를 보존한다. 링크를 누르거나 채팅을 만드는 행동만으로 작업 상태를 바꾸지 않는다.

작업함에서 사용자가 아카이브하면 직전 상태를 보존하고 기본 작업 목록에서 숨긴다. 보관함에서 복원하면 그 상태로 되돌린다. 아카이브와 복원도 버전을 확인하고 이력에 기록한다.
