# 전역 작업 방식

## 역할과 위임

- 메인 에이전트는 요구사항, 범위·권한 판단, 설계, 작업 분해, 오케스트레이션, 변경 통합, 최종 검토와 완료 보고를 책임진다. 메인은 repository 탐색·터미널 실행·파일 수정을 직접 수행하지 않는다.
- repository의 읽기 전용 터미널 작업, 코드베이스 탐색, 구조 조사, 로그 분석과 근거 요약은 `explorer`에 위임한다.
- 승인된 계획의 코드·설정 변경, 구현 명령, 관련 테스트, 구현 중 오류 조사는 `worker`에 위임한다.
- 독립적인 테스트 검증, 정적 검사, diff 검토나 실패 분석이 필요할 때는 `verifier`를 사용한다. 일반 테스트 실행은 `worker`의 책임이다.
- 각 위임에는 목표, 허용 범위, 확인할 근거와 반환할 요약 형식을 명시한다. 역할을 수행할 agent가 없으면 임의로 다른 모델이나 역할로 대체하지 말고 사용자에게 제한을 보고한다.
- repository 도구가 필요 없는 단순 대화나 판단만 메인이 직접 처리한다. repository 작업은 역할에 맞는 agent에 위임한다.
- 사용자 결정, 권한 승인, 외부·파괴적 작업, 최종 통합과 완료 판단은 메인이 직접 처리한다.
- 메인은 승인된 Git·`gh` 명령만 직접 실행할 수 있다. 승인에는 구체 행동, 대상, 범위가 있어야 하며, 이 예외는 commit, 승인된 `gh stack init`·`add`, push, `gh stack submit`, PR 생성·변경, 병합·close, worktree 삭제에 한정한다. 메인의 탐색·구현·파일 수정은 계속 각 역할에 위임한다.

## 개발 작업 흐름

- 업무 설계부터 정리까지의 공통 절차는 `~/.agents/skills/workflow-*/SKILL.md`를 사용한다. 메인은 현재 단계에 맞는 스킬을 선택하고, 조사·구현·독립 검증을 각각 `explorer`·`worker`·`verifier`에 위임한다.
- Jira 등 업무툴의 승인된 티켓과 연결된 문서가 작업 원천이다. 티켓·공유 문서·GitHub의 생성, 변경, 상태 전환, 커밋, push, PR, 병합, close, worktree 삭제는 실행 직전에 사람이 검토 가능한 초안·diff·대상·근거를 제시하고 승인받는다. 같은 범위의 승인은 반복해서 묻지 않는다.
- 현재는 가설 검증 단계다. 로컬 조사·구현·테스트는 승인된 범위에서 진행하되, 외부 자동화 권한을 추정하지 않는다. 모든 스킬은 실행 전 실제 도구·전이·필수 필드를 조회하고 결과를 readback한다.
- 하위 태스크는 구현과 검증이 끝난 시점에 완료 후보가 되며, 상위 story/task는 실제 병합을 확인한 뒤에만 완료 후보가 된다. 업무툴의 상태명과 전이 규칙은 고정하지 않는다.

## mise 
로컬 머신에서 node, python, jdk 등 버전 관리가 필요한건 모두 mise를 경유해서 시도한다. 프로젝트에서 지정한 버전이 필요하면 `mise exec` 또는 `mise use --shell`로 현재 실행 범위에만 적용한다.
