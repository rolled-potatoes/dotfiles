# 전역 작업 방식

## 서브에이전트 위임

- 메인 에이전트는 사용자 요구사항, 범위와 권한 판단, 작업 분해, 변경 통합, 최종 검증 및 완료 보고를 책임진다.
- 복잡한 작업에서 서로 독립적인 하위 문제가 둘 이상이고 병렬 처리로 탐색 시간 또는 메인 컨텍스트 오염을 줄일 수 있으면, 각 하위 문제를 하나의 서브에이전트에 위임한다.
- 서브에이전트 위임에 적합한 작업은 읽기 중심의 코드 탐색, 서로 다른 모듈의 조사, 재현·진단, 테스트 실행, 로그 분석, 문서·구조 요약이다.
- 각 서브에이전트 요청에는 목표, 허용 범위, 확인할 근거, 반환할 요약 형식을 명시한다. 서브에이전트는 원시 탐색 로그 대신 결론, 근거 위치, 실행한 검증, 남은 위험을 간결히 반환하게 한다.
- 서로 의존하지 않는 조사와 검증만 병렬로 실행한다. 현재 런타임의 동시 실행 한도를 넘지 않는다.
- 단순하고 자족적인 작업, 순차 의존성이 강한 작업, 서브에이전트 조정 비용이 작업 자체보다 큰 작업에는 서브에이전트를 사용하지 않는다.
- 여러 에이전트가 같은 파일이나 같은 변경 단위를 동시에 수정하지 않게 한다. 쓰기 작업은 한 에이전트가 소유하고, 다른 에이전트는 읽기 전용 조사 또는 검증만 수행한다.
- 사용자 결정, 권한 승인, 외부·파괴적 작업, 최종 통합과 완료 판단은 메인 에이전트가 직접 처리한다.
- 서브에이전트는 추가 모델·도구 호출을 사용하므로 총 토큰 사용량을 줄인다고 가정하지 않는다. 메인 컨텍스트 보존 또는 독립 작업의 병렬성이 명확한 경우에만 위임한다.
