# 프로젝트 산출물 계약

## 규칙과 문서

루트 `AGENTS.md`는 짧게 유지하며 공통 규칙과 상세 SSOT의 진입점만 둔다. 조사로 독립 규칙이 확인된 디렉터리에만 하위 `AGENTS.md`를 두고 루트에 반복하지 않는다. 코드·테스트·디렉터리·의존 방향·검증·커밋·PR 규칙은 실제 프로젝트 근거로 작성한다.

각 새 `AGENTS.md`와 같은 디렉터리에는 상대 링크 `CLAUDE.md → AGENTS.md`를 만들 수 있다. 대상 경로가 없는 경우에만 만든다. 일반 파일 또는 다른 대상을 가리키는 링크가 있으면 절대 덮어쓰지 말고, 현재 대상과 제안 diff를 사용자에게 제시한다.

기존 docs 구조가 있으면 그 구조를 SSOT로 사용한다. 없으면 최소한 다음 사실의 단일 진입점을 제안한다.

- 아키텍처와 주요 경계
- 코드·테스트·디렉터리 컨벤션
- 하네스 사용법과 검증 방법
- 커밋·PR 규칙
- 작업 유형별 참조 문서와 프로젝트 Skill 라우팅

프로젝트 로컬 Skill은 반복 작업, 프로젝트 고유 판단, 검증 품질 개선이라는 세 조건이 모두 증명될 때만 생성한다. 각 Skill은 입력, 적용 조건, SSOT, 승인·중단 조건, 검증만 담고 `AGENTS.md`를 복제하지 않는다.

## 작업 증거

사용자가 다른 위치를 승인하지 않으면 아래 구조를 Git 자산으로 사용한다.

```text
.agents/work/<task-id>/
├── goal.md
├── plan.md
├── implement.md
├── validate.md
├── report.md
└── loops/
    └── loop-01/
        ├── plan.md
        ├── implement.md
        ├── validate.md
        └── report.md
```

각 파일에는 역할에 맞는 사실만 기록한다.

- `goal.md`: 배경, 범위, 제약, 검증 가능한 완료 조건과 사람 검증 조건
- 루트 `plan.md`: 승인된 As-Is, To-Be, 파일, 위험, 검증, 승인 기록
- 루트 `implement.md`: 전체 변경과 핵심 판단, 계획 대비 차이
- 루트 `validate.md`: 최종 명령, 결과, 스냅샷, 수동·시각 검증 증거
- 루트 `report.md`: 완료 판정, 남은 위험, 문서 영향, 커밋 준비 정보
- 루프 파일: 직전 증거·가설·실행·실제 변경·검증·상태 판정과 `failure_key`

각 루프 plan에는 `created_at`, report에는 `finished_at`, validate에는 `snapshot`과 결과 상태를 기록한다. 사람이 필요한 완료 조건은 goal과 validate에 필요한 행동·기대 결과·제출 증거를 명시하고, report에 `human_verification_status: passed`가 없으면 성공 처리하지 않는다.

비밀값, 캐시, 빌드 산출물, 재생성 가능한 대용량 증거만 상황에 맞춰 `.gitignore`로 제외한다. 제외 이유와 대체 가능한 재현 방법은 문서화한다. 템플릿 버전 또는 적용 버전 파일은 만들지 않는다.
