# 프로젝트 조사 기준

조사는 프로젝트에 맞는 최소 하네스를 설계하기 위한 근거 수집이다. 비밀값의 내용은 읽거나 출력하지 않는다. `.env`, 인증서, 키, 토큰, credential 파일은 존재 여부와 Git 제외 여부만 확인한다.

## 대상과 기존 상태

다음을 먼저 확인한다.

- 현재 Git 저장소와 실제 프로젝트 루트, 중첩 저장소와 workspace 경계
- `git status --short`, 기본 브랜치를 알 수 있는 로컬 설정, 기존 branch·worktree 관례
- 루트와 대상 하위 디렉터리의 `AGENTS.md`, `CLAUDE.md`, 심볼릭 링크 대상
- 기존 `.agents/`, Skill, 규칙, 작업 로그, 하네스, hook, CI/CD, PR 템플릿
- 사용자 변경, 생성물, 캐시, 대용량 증거의 현재 Git 정책

remote, 기본 브랜치, 원격 최신 상태는 추정하지 않는다. fetch, pull, branch 또는 worktree 생성은 상태 변경이므로 별도 권한을 요청한다.

## 기술과 검증 근거

실제 manifest, lockfile, CI 설정, 실행 스크립트와 코드 구조에서 다음을 수집한다.

- 언어, 프레임워크, 런타임과 확인 가능한 버전
- 패키지 관리자, lockfile, monorepo package/workspace 경계
- 프론트엔드, 백엔드, 모바일, 인프라, 배포 구성과 의존 방향
- build, format, lint, type check, unit/integration/e2e test, production build, deploy-preflight 명령
- CI에서 실제로 실행하는 명령과 로컬 재현 가능성
- 공개 API, 서버 계약, 데이터 모델, migration, 도메인 규칙의 경계
- 아키텍처·운영·컨벤션 문서의 SSOT와 코드와의 불일치
- 시각·기기·권한·외부 환경처럼 사람이 판정해야 하는 완료 조건 및 가능한 증거 장치

실행 명령은 파일 근거와 함께 기록한다. 없는 명령을 관례로 채우지 않는다. 사람이 필요한 조건은 스크린샷, 자동 브라우저 검사, 로그, 재현 가능한 체크리스트 또는 사용자 결과 입력 중 프로젝트에 가능한 방식을 제안한다.

## 판정

다음 중 하나만 선택하고 근거를 계획에 적는다.

| 판정 | 의미 |
| --- | --- |
| 신규 구축 | 하네스 계약과 증거 구조가 없거나 실제 실행 게이트가 없음 |
| 부분 하네스 확장 | 일부 문서·명령·검사만 있고 계약의 중요한 부분이 빠짐 |
| 기존 하네스 업데이트 | 실행 가능한 기존 흐름은 있으나 안전하게 보완할 부분이 확인됨 |
| 사용자 판단 필요 | 충돌하는 규칙, 불명확한 소유자, 비호환적 링크·명령·보안 위험이 있음 |

기존 하네스는 명령 의미, 파일 책임, 호출자, 검증 범위, Git 영향과 부족한 게이트를 비교한다. 교체를 전제하지 않으며, 불확실하면 변경을 제안만 하고 승인 전에는 작성하지 않는다.
