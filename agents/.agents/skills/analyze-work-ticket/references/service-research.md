# 서비스별 조사 경로

이 절차는 현재 세션에서 실제 사용 가능한 연결 도구와 그 스키마를 먼저 확인한 뒤 적용한다. 도구명이나 필드를 추정해 호출하지 않는다. 서비스 도구가 없거나 읽기 권한이 없으면 해당 자료를 조사 한계에 기록한다.

## 공통

- 직접 링크, 작업 ID, 문서명, 명시적 언급을 연결 후보로 사용한다. 검색 결과는 연결 근거를 확인한 뒤에만 본 조사 자료로 채택한다.
- 각 목록·검색·댓글·스레드는 cursor 또는 page token이 있으면 마지막 페이지까지 읽는다.
- 첨부는 제공되는 읽기 도구와 접근 가능한 범위에서만 확인한다. 미지원 형식·권한 오류·크기 제한은 한계다.
- 작성·결정 날짜는 해당 메시지·댓글·이력의 날짜처럼 내용에 연결된 근거만 쓴다. 조회 시각과 파일 수정일·문서 수정일은 개별 결정의 날짜를 증명하지 않는다. 날짜를 확인할 수 없는 내용은 날짜가 확인된 내용 뒤에 `날짜 미확인`으로 표시한다.

## Jira

- 접근 가능한 Atlassian 리소스를 확인한 뒤, 직접 키 또는 명시적 관계가 있는 이슈를 읽는다.
- JQL 검색 결과는 next-page 토큰을 끝까지 따라간다. 이슈 본문, 연결 이슈, 확인 가능한 댓글·첨부·참조를 조사한다.
- 댓글·첨부의 세부 읽기 방식은 현재 Jira 도구의 discover 또는 schema 확인 후에만 사용한다.

## Notion

- `notion-auto-delegate`를 사용할 수 있으면 Notion 링크·검색·댓글 조사를 Notion MCP 하위 에이전트에 위임한다.
- 페이지를 읽을 때 토론과 전사 정보가 지원되면 포함하고, discussion 식별자가 있으면 댓글과 하위 블록을 확인한다. 페이지·댓글의 명시적 참조를 따라간다.
- 첨부는 페이지 읽기 결과 또는 제공된 읽기 도구로 접근할 수 있는 것만 확인한다.

## Slack

- 기본적으로 공개 채널 검색과 직접 지정된 채널 읽기만 사용한다. 비공개 자료 검색은 사용자의 사전 명시 동의가 있을 때만 사용한다.
- 검색된 메시지는 원문과 스레드를 읽고, 파일 ID가 있으며 읽기 도구가 제공될 때만 첨부를 확인한다.

## Google Docs와 Google Sheets

- Drive 검색으로 문서명·명시적 참조를 확인하고, 후보의 URL·메타데이터를 기준으로 관계를 검증한 뒤 읽는다.
- Docs는 본문과 제공되는 댓글을 확인한다. Sheets는 메타데이터로 관련 시트와 범위를 확인한 다음 필요한 범위·셀·댓글만 읽는다.
- Drive 파일 이력은 자료의 변화를 찾는 보조 근거다. 파일 수정 시각만으로 개별 요구나 결정의 날짜를 확정하지 않는다.

문서·스프레드시트 전용 작업이 필요하면 각각 `google-drive:google-docs`, `google-drive:google-sheets`, `google-drive:google-drive` 스킬의 읽기 절차를 따른다.
