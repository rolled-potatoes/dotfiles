# 원격 반영과 PR 생성

## 실행 전 검토

1. 작업 범위와 현재 브랜치를 확인한다. staged·unstaged diff와 untracked 파일을 살펴보고 관련 변경만 고른다. 커밋할 변경이 있으면 [commit](../commit/SKILL.md)을 읽고 커밋 단위와 메시지를 준비한다. 다른 작업의 staged 변경도 보존한다.
2. 사용자 지정과 저장소 설정에서 push할 저장소·브랜치를 확인한다. 실제 원격 ref를 조회하고 필요한 이력을 fetch하여 양쪽의 고유 커밋을 확인한다. 새 원격 브랜치라면 분기 기준부터 포함될 커밋을 검토한다. 목적지가 불분명하면 미확정 대상만 묻는다. fast-forward가 불가능하면 갈라진 이력을 알리고 중단한다.
3. PR 생성 요청이면 사용할 GitHub 도구와 입력 필드를 확인하고 base 저장소·브랜치와 head 저장소·브랜치를 특정한다. 이 조합의 열린 PR을 조회한다. 새 PR이 필요하면 [create-pr](../create-pr/SKILL.md)의 규칙으로 base와의 전체 차이 및 이번에 포함할 로컬 변경을 반영한 제목·본문을 준비한다.
4. 첫 변경 직전에 새 커밋과 함께 push될 기존 커밋 각각의 diff·메시지, push 대상과 선정 근거를 한 번에 보여주고 승인받는다. PR 생성 시 base·head와 제목·본문 초안도 포함한다. 기존 PR이 있으면 URL과 이번 push가 해당 PR에 반영된다는 점을 보여준다. 수행할 변경이 없으면 조회 결과를 바로 반환한다.

## 실행과 결과 확인

- 승인된 변경만 stage하고 staged diff를 확인한 뒤 commit 절차를 수행한다. 목적지와 내용이 승인 범위에 있으면 같은 승인을 재사용한다. 검토 후 diff나 대상이 바뀌면 달라진 부분을 제시하고 다시 승인받는다.
- 미반영 커밋이 있거나 새 원격 브랜치를 게시할 때만 승인한 단일 ref로 일반 push한다. 대상 ref의 SHA를 다시 조회해 로컬 HEAD와 대조한다.
- PR 생성 요청에서는 push가 확인되면 같은 base·head의 열린 PR을 다시 조회한다. 있으면 그 URL을 반환하고, 없으면 승인한 문안으로 생성한다. PR을 다시 읽어 URL과 양쪽 저장소·브랜치를 확인한다.
- 실패하면 확인된 마지막 단계와 원인을 알린다. 재시도 전 로컬 HEAD, 원격 ref, 필요한 경우 열린 PR을 다시 조회하고 남은 단계만 실행한다. 결과에는 반영한 커밋, 원격 브랜치와 확인한 SHA, 해당하는 경우 PR URL을 담는다.
