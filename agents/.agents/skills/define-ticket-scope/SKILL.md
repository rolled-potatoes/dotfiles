# 작업 티켓 작업 방향성 정리하기. 

작업의 티켓의 방향성을 정리하여 작업 범위, 범위가 아닌것, 인수조건을 정의한다. 작업을 위해서는 다음의 순서로 진행한다. 작성은 명확한 표현과 단조롭고 장황하지 않는 간략한 표현을 지향한다.

1. 티켓 내부의 관련 문서를 읽어서 정보를 수집한다. 
2. 읽은 정보를 취합하여 요구사항 달성에 필요한 기능/시나리오/스토리로 나열한다. 
3. 나열한 항목을 달성을 검통할 수 있는 인수조건을 나열한다. 
4. 결정 사항 이외에 작업하는데 명확하지 않거나 규칙이 어긋나는 부분이 있다면 명확화 질문을 통해 논의한다. 이를 기반으로 2,3을 명확히 한다. 
5. 위 내용을 취합하여 티켓의 "범위" & "범위 제외", "인수조건", "결정 사항", "할 일" & "미결사항"을 작성하는 초안을 작성하고 검토를 받는다. 
6. 검토가 통과 되어 승인하면 편집 가능한 문서로 작성하여 제시한다. 

## 티켓 구성

- 핵심 스토리
- 협업 담당자
- 작업 범위
- 범위 제외
- 인수조건
- 결정 사항
- 미결 사항 | 할 일
- 관련 문서

"미결 사항 | 할 일" 은 체크박스로 표시한다. 

## 인수조건 작성

- 인수조건은 `카테고리 | 상세내역 | 근거` 표로 작성한다.
- 카테고리는 실제 작업에 맞게 조정하며, 해당하지 않는 항목은 생략한다.
- 근거에는 해당 조건이 작성된 문서의 직접 링크와 정책 ID·시트 범위·절·화면 위치를 표시한다.
- 같은 행의 조건들이 서로 다른 근거를 가지면 상세내역과 근거의 대응 관계를 명시하거나 행을 나눈다.
- 문서에 없는 신규 결정은 `이번 논의에서 확정 — 문서 반영 전`으로 표시한다.
- 확인하지 못한 위치나 링크는 추정하지 않는다.

### 인수조건 형식


| 카테고리 | 상세내역 | 근거 |
|---|---|---|
| 조회·검색 | 검색 초기화 시 검색어를 지우고 첫 페이지를 조회한다. | [정책서 해당 위치](링크) · 정책 ID |
| 등록·수정 | 단어는 필수, 설명은 선택으로 입력한다. | [정책서 해당 위치](링크) · 정책 ID |
