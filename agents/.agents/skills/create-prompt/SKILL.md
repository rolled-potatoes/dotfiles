# 프롬프트 생성하기

사용자가 다른 agent 또는 session에서 실행할 수 있도록, 근거가 추적되는 작업 범위와 판정 가능한 인수 조건·검증 명세를 먼저 만든 뒤 실행 프롬프트를 구성한다. 이 스킬은 계획과 프롬프트 생성에 한정하며 대상 작업을 직접 구현하거나 검증 완료를 주장하지 않는다.

## 작업 수행 

### 1. 근거와 환경 파악

현재 대화, 사용자가 지정한 원천 문서, 필요한 범위의 프로젝트 상태를 확인한다. 이미 확인한 사실은 반복 조사하지 않는다.

요구사항·변경 범위·인수 조건은 다음 근거에만 둔다.

- 사용자의 명시적 요구
- 확인한 원천 문서와 프로젝트 사실
- 대화에서 확정된 결정

기존 코드는 현재 동작을 확인하는 근거일 뿐, 사용자가 원하는 동작을 뜻하지 않는다. 근거 없는 정책·동작·예외 처리·개선 사항을 작업 범위에 추가하지 않는다. 필요성을 발견하면 제안 또는 미결정 질문으로 분리한다.

### 2. 인수 조건과 검증 명세 초안

각 인수 조건에 `인수조건-01`처럼 식별자를 붙이고, 시작 조건·사용자 또는 시스템의 행동·기대 결과를 관찰 가능하게 작성한다. 모호한 품질 표현은 측정·판정 가능한 조건으로 바꾸거나 미결정으로 둔다.

각 인수 조건마다 실행 가능한 검증 명세를 연결한다. 검증 명세에는 다음을 포함한다.

- 관련 테스트 층위와 검증 목적
- 필요한 데이터·상태와 입력
- 수행 행동
- 관찰 지점, 기대값, 합격·실패 기준
- 실제 의존성 또는 대체 의존성, 그리고 그 한계

실행 명령은 확인한 명령만 적는다. 알 수 없으면 탐색 지시를 적고 명령을 추측하지 않는다. 오류·경계·회귀 사례는 변경 위험에 비례해 포함한다. 모든 작업에 E2E, TDD, 또는 새 자동화 테스트를 강제하지 않는다.

### 3. 빈틈 확인, 조사와 질의

인수 조건과 검증 명세를 양방향으로 대조한다. 모든 인수 조건에는 판정 가능한 검증 수단이 있어야 하며, 각 검증은 어떤 인수 조건을 증명하는지 밝혀야 한다. 성공 사례만으로 놓치는 관련 오류·경계·회귀가 있는지 확인한다.

확인 가능한 사실은 먼저 조사한다. 조사해도 사용자 의도·제품 정책·완료 기준을 결정할 수 없고, 그 답이 인수 조건 또는 검증 결과를 바꾼다면 번호를 매긴 질문으로 묻는다. 테스트를 설계하다 새 정책이 필요해져도 인수 조건을 임의로 확장하지 말고 같은 방식으로 사용자 결정으로 되돌린다.

조사 결과 또는 사용자 답변을 받으면 관련 인수 조건과 검증 명세를 함께 수정하고 양방향 대조를 반복한다.

답이 없는 미결정은 가정으로 확정하거나 최종 구현 지시에 넣지 않는다. 미결정과 무관한 확정 범위는 독립적으로 진행할 수 있다. 그러나 필수 미결정 때문에 인수 조건 또는 검증의 합격 기준을 정할 수 없으면, 최종 실행용 프롬프트를 확정하지 않고 초안과 미결정을 제시한다. 구현 세부 선택은 승인된 범위와 검증 기준 안에서 실행 agent가 판단할 수 있지만, 이를 제품 정책으로 넓히지 않는다.

### 4. 계획과 프롬프트 작성

최종 지시마다 근거를 다시 대조하여 근거 없는 추가 사항을 제거한다. 충분한 정보란 질문 횟수가 아니라 모든 인수 조건에 판정 가능한 검증 수단이 연결된 상태다.

최종 프롬프트에는 다음을 포함한다.

- 목표와 확인한 원천
- 변경 범위와 제외 범위
- 인수 조건별 근거, 시작 조건·행동·기대 결과
- 인수 조건별 검증 명세와 알려진 한계
- 구현·검증의 권장 순서
- 인수 조건별 통과 근거, 실행한 검증, 미실행·미결정 항목을 구분하는 완료 보고 기준

명세가 생략되지 않도록 고정 글자 수 제한을 두지 않는다. 중복 설명은 줄이되 인수 조건과 검증의 판정 기준은 생략하지 않는다.

## 작업 규칙 

- 작업 내용이 없으면 스킬을 종료한다.
- 질문은 답변을 인수 조건과 검증 명세에 매핑할 수 있도록 번호를 매긴다. 이미 답한 질문을 반복하지 않는다.
- 모든 인수 조건에 판정 가능한 검증 수단이 있으면 질문 없이 최종 프롬프트를 작성한다.
- 답변받지 못한 필수 미결정은 초안에 명시하고, 가정·위험으로 치환해 구현 범위를 확정하지 않는다.
- agents.md 에 포함된 내용이나 작업 스킬 호출은 명세하지 않는다. 이미 실행 환경에서 참조할 수 있기 때문이다.

## 결과물 

최종 프롬프트 또는 미결정이 남은 초안을 복사 가능한 마크다운 코드 블럭으로 제시한다.
