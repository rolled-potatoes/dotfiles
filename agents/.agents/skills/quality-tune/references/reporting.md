# 메인 실행 보고 규칙

메인이 공통 운영 규칙 및 조정·판단 규칙과 함께 읽고 실행 결과를 기록한다. 이 문서는 전문가의 최초 연구 지침으로 전달하지 않는다.

## 결과 확인

기존 독립 검토 체계에서 관련 목표의 전후 근거와 부작용을 확인하고 목표별 검토 여부와 근거를 취합한다. 테스트 통과·전문가 합의만으로 개선 효과가 입증됐다고 판단하지 않는다. 성능은 같은 조건의 실측이 없으면 개선·유지 여부를 미확인으로 남긴다. 검증 가능성과 실제 모니터링 신호 확인도 구분한다. 결과를 확인할 수 없는 항목은 미측정 또는 미확인으로 기록한다.

## 공용 실행 보고서

메인은 각 호출의 시작 시각과 충돌하지 않는 실행ID를 먼저 정해 조정자에게 전달한다. 실행ID는 프로젝트 간에도 겹치지 않도록 UUID 같은 고유값을 사용한다. 실제 시계를 읽고 날짜·시각과 시간대를 기록하며 세션ID를 임의로 만들어 쓰지 않는다. 같은 실행을 재개하면 실행ID와 최초 시작 시각을 유지하고 중단·재개 시각을 남긴다. 다른 세션이 같은 실행을 동시에 기록하지 않는다.

프로젝트별 세 파일은 상세 기록의 원본으로 유지한다. 메인은 `~/Documents/Codex/quality-tune-results/reports/<실행ID>.md`에 시작 시각과 진행 중 상태를 가능한 한 먼저 저장한다. 최종 검토와 가능한 경우 handoff.md 저장 확인 후 같은 보고서에 결과와 종료 시각을 기록하고 다시 읽어 확인한다. 파일명은 실행ID로 구분하며 다른 실행의 파일을 덮어쓰지 않는다. 조정자에게 공용 보고서 수정을 요구하지 않는다. 변경 없이 종료, 일부 보류, 시작 전 조건 불충족과 중단도 확인 가능한 내용으로 기록한다. 프로젝트나 큰 작업 경로를 식별하지 못했을 때도 공용 보고서는 남기되 프로젝트별 기록을 임의로 만들지 않는다.

보고서에는 다음을 남긴다.

- 실행ID, 확인 가능한 실제 세션ID, 프로젝트·작업, 최종 상태와 원본 기록·변경 위치. 확인하지 못한 값은 미확인으로 표시한다.
- 시작·종료 시각과 총 경과 시간. 종료 시각은 최종 검토와 결과 정리를 마친 뒤 기록하며, 시작 전 중단이면 중단 시각을 쓴다. 총 시간은 최초 시작부터 종료까지 실제로 흐른 시간으로, 병렬 에이전트별 시간을 합산하지 않는다.
- 확인 가능한 사용자 확인·외부 조건 대기 및 중단 구간. 대기 시간이 완전히 확인된 경우에만 총 시간에서 겹치지 않는 대기를 제외한 시간을 별도로 표시한다. 이는 에이전트의 실제 연산 시간이 아니다. 시각이나 대기를 확인할 수 없으면 추정하지 않고 미확인으로 둔다.
- 사용량·비용의 값, 범위와 출처를 실행 환경이 실제 제공하는 경우에만 기록한다. 전체 실행을 포함하는지 불명확하면 범위를 명시하고 전체 비용으로 취급하지 않는다. 제공되지 않으면 확인 불가로 둔다.
- 문제와 변경 또는 유지 이유, 세 품질 목표별 기준·결과·판단 근거, 실제 수행한 검사, 이견·부작용·미검증 사항. 세 목표 외 전문가별 주요 발견과 남은 이견도 별도로 남긴다.

각 목표는 `개선 근거 확인`, `악화 근거 확인`, `변화 없음`, `효과 불명`, `미측정`, `해당 없음` 중 하나로 구분한다. `변화 없음`은 비교 가능한 근거로 유의미한 변화가 확인되지 않은 경우, `효과 불명`은 평가했으나 판단 근거가 부족한 경우, `미측정`은 관련되지만 평가하지 못한 경우다. 이는 메인의 결과 정리 기준이며 전문가의 제안 범위를 제한하지 않는다. 원본이 없어져도 주요 결론을 이해할 수 있게 요약하되 긴 코드·원문·비밀값은 복사하지 않는다.

공용 경로의 접근 권한은 세션과 환경에 따라 다르므로 저장 가능 여부를 확인한다. 저장이 불가능하면 권한을 우회하거나 다른 위치를 공용 기록처럼 보고하지 않는다. 가능한 경우 프로젝트별 handoff.md에 보고서 미저장과 이유를 남기고 사용자에게 알린다. 공용 보고서를 조회할 때는 각 실행 파일을 읽어 목록·비교를 만들며, 확인되지 않은 효과·사용량을 채워 넣지 않는다.
