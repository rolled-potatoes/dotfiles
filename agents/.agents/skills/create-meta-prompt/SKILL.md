# Create Meta Prompt

다른 Codex가 추가 설계 결정을 하지 않고 작업을 시작할 수 있는 하나의 실행용 Markdown 프롬프트를 만든다. 프롬프트를 만드는 동안 본 작업은 수행하지 않는다.

## 시작 시 읽을 자료

항상 [프롬프트 산출물 계약](references/prompt-contract.md)을 끝까지 읽고 필수 구조, 선택 구조, 실행 체크리스트와 평가 게이트를 적용한다.

## 책임 경계

- 신규 작업 프롬프트만 작성한다. 제공된 기존 프롬프트의 첨삭이나 재작성은 수행하지 않는다.
- 본 작업의 코드, 설정, 문서, 데이터 또는 외부 시스템을 변경하지 않는다.
- 프롬프트 작성을 위한 읽기 전용 조사만 수행한다. 사용자가 프롬프트 파일 저장을 명시적으로 요청했을 때만 해당 파일을 작성한다.
- 확정된 구현 계획의 사실성 검증은 `validate-plan`의 영역으로 남긴다.
- 저장소 지침과 설치가 확인된 스킬·도구만 생성 프롬프트에 명시한다. 존재한다고 추측하지 않는다.
- 사용자의 명시적 지시와 현재 실행 환경의 상위 지침을 생성 프롬프트로 우회하거나 약화하지 않는다.

## 1. 요청과 대상 고정

다음 항목을 입력에서 먼저 추출한다.

- 본 작업의 목표와 필요한 결과
- 결과를 사용할 사람 또는 시스템
- 대상 Codex가 수행할 요청 유형
- 사용자가 제공한 배경, 결정, 제약과 성공 기준
- 대상 저장소, 파일, 서비스, 외부 시스템과 실행 환경
- 생성 프롬프트를 대화로 받을지 파일로 저장할지

사용자가 파일 저장을 요청하지 않았다면 대화에 반환하는 것으로 확정하고 묻지 않는다.

## 2. 근거 조사

질문하기 전에 사용자가 제공한 자료와 접근 가능한 환경을 읽기 전용으로 조사한다.

1. 저장소의 `AGENTS.md`, 관련 코드·문서·설정·테스트·스키마를 찾는다.
2. 기존 템플릿, glossary, 비슷한 구현과 적용 가능한 스킬을 확인한다.
3. 특정 문서, URL, 버전, 일정 또는 현재 상태에 의존하면 해당 원본이나 최신 1차 자료를 확인한다.
4. 확인한 사실을 파일과 줄, 명령 결과 또는 출처 링크로 추적 가능하게 기록한다.
5. 자료 사이의 충돌과 확인할 수 없는 내용을 분리한다.

조사 과정에서 본 작업을 미리 구현하거나 외부 시스템을 변경하지 않는다. 쓰기, 결제, 삭제, 배포, 메시지 발송처럼 상태를 바꾸는 작업은 프롬프트 작성의 근거 수집 수단으로 실행하지 않는다.

## 3. 요청 유형과 권한 분류

본 작업을 다음 중 하나로 분류하고 프롬프트에 허용 범위를 명시한다.

- **답변·설명·검토·보고**: 읽기 전용 조사와 결과 전달만 허용한다.
- **진단**: 원인과 근거를 찾되 사용자가 수정까지 요청하지 않았다면 변경을 허용하지 않는다.
- **변경·구축**: 명시된 대상의 구현, 필요한 검증과 안전한 후속 작업까지 허용한다.
- **자동화·모니터링**: 반복 조건, 주기, 종료 조건과 외부 상태 변경 범위를 명시한다.

프롬프트에 없는 권한을 일반적인 관행이라는 이유로 추가하지 않는다. 외부 쓰기나 복구하기 어려운 작업에는 정확한 대상, 사전 확인, 성공 확인과 실패 처리 조건을 포함한다.

### 외부·파괴적 작업 결정 게이트

삭제, 결제, 환불, 배포, 권한 변경, 메시지 발송 등 복구하기 어렵거나 다른 사람에게 영향을 주는 작업은 다음을 사용자 결정으로 확인하기 전까지 최종 프롬프트를 만들지 않는다.

- 정확한 계정, 조직, 저장소, 채널, 환경 또는 리소스
- `모두`, `실패한 항목`, `오래된 항목` 같은 표현의 선택 조건과 제외 조건
- 기간, 보존 기준, 최대 개수 또는 실행 범위
- 실행 전 후보 검토와 최종 승인 시점
- 백업·복구 가능성 및 부분 실패 시 계속할지 중단할지
- 성공 확인 방법과 결과 보고 범위

현재 작업 디렉터리, 로그인된 계정, 기본 프로젝트, 첫 검색 결과를 파괴적 작업의 대상으로 임의 선택하지 않는다. 외부 API의 enum이나 상태 이름으로 사용자의 모호한 표현을 임의 번역하지 않는다.

## 4. 지식과 결정 분리

수집한 내용을 다음 네 종류로 구분한다.

- **사실**: 입력 자료나 조사 근거로 확인한 내용
- **결정**: 사용자가 명시적으로 선택했거나 승인한 내용
- **가정**: 결과를 바꾸지 않는 안전한 기본값
- **미결 사항**: 선택에 따라 범위, 동작, 데이터, 위험 또는 결과가 달라지는 내용

근거 없는 세부사항을 사실이나 결정으로 채우지 않는다. 가정이 결과를 실질적으로 바꿀 수 있으면 미결 사항으로 올린다. 새 공개 인터페이스, 지원하지 않는 입력의 동작, 오류 정책, 제품 동작, 추가 산출물은 안전한 가정으로 취급하지 않는다.

대상 Codex가 기존 구조 안에서 가역적인 코드 수준 구현 선택을 하는 것은 허용한다. 반면 사용자 경험, 호환성, 데이터, 권한, 외부 효과나 성공 기준을 바꾸는 선택은 먼저 사용자 결정으로 확정한다.

## 5. 사용자 결정 확인

조사로 해결할 수 없는 중요한 미결 사항만 질문한다.

- 한 번에 1~3개의 짧은 질문을 한다.
- 가능하면 2~3개의 상호 배타적인 선택지와 근거 있는 권장안을 제시한다.
- 각 선택지가 범위, 결과, 위험 또는 비용에 미치는 차이를 한 문장으로 설명한다.
- 답변 뒤 남은 미결 사항을 다시 점검한다.

목표, 성공 기준, 범위, 권한 또는 핵심 동작이 확정되지 않았으면 최종 프롬프트를 생성하지 않는다. 사용자가 결정을 제공할 수 없으면 누락된 결정과 영향을 짧게 보고하고 중단한다. 빈칸이나 임시 선택이 포함된 초안을 대신 내보내지 않는다.

## 6. 실행 프롬프트 작성

모든 중요한 결정이 확정되면 `references/prompt-contract.md`에 따라 하나의 Markdown 문서를 작성한다.

- 대상 Codex에게 직접 지시하는 명령형 문장으로 쓴다.
- 한국어 설명을 기본으로 하고 코드 식별자, API, 공식 명칭과 확인된 canonical English만 유지한다.
- 목표, 범위, 결정, 작업 순서, 산출물과 검증을 서로 추적할 수 있게 작성한다.
- 작업에 필요하지 않은 선택 섹션은 만들지 않는다. `해당 없음`을 채우기 위해 빈 절을 추가하지 않는다.
- 파일과 줄, URL, 버전 등 대상 Codex가 다시 확인할 수 있는 근거 위치를 포함한다.
- 저장소 지침 준수, 사용자 변경 보존과 최소 범위 원칙을 필요한 작업에 명시한다.
- 테스트 이름, API 구조, 오류 정책, 배포 단계처럼 확인되지 않은 세부사항은 발명하지 않는다.
- 요청하지 않은 수정 권고, 비교안, 문서, 테스트 파일 또는 후속 작업을 산출물에 추가하지 않는다.
- 새 옵션이나 API를 추가할 때 지정되지 않은 입력·오류 동작은 기존 계약을 보존하도록 두고, 기존 계약으로 결정할 수 없으며 결과에 영향을 주면 사용자에게 묻는다.

## 7. 품질 게이트

전달 전에 산출물 계약의 평가 게이트를 모두 적용한다. 하나라도 실패하면 프롬프트를 수정하거나 필요한 결정을 추가로 질문한다.

특히 다음 실패를 허용하지 않는다.

- 빈 placeholder, TODO, 선택되지 않은 대안
- 입력이나 근거에 없는 기능, 정책, 권한 또는 시스템
- 요청하지 않은 공개 동작, 오류 처리, 권고 또는 추가 산출물
- 본 작업을 프롬프트 작성 중 이미 수행했다는 표현
- 성공 기준으로 증명되지 않는 일반적인 테스트 목록
- 범위와 권한을 넘어서는 배포, 삭제, 메시지 발송 또는 외부 쓰기
- 대상 Codex가 다시 제품 결정을 내려야만 실행할 수 있는 모호한 지시

## 결과 전달

- 기본적으로 `# Agent 작업 프롬프트`로 시작하는 하나의 복사 가능한 Markdown 문서만 반환한다.
- 전체 문서를 하나의 코드 블록으로 감싸지 않는다. 문서 안에 필요한 코드 블록은 그대로 유지한다.
- 프롬프트 파일 저장을 요청받았다면 저장 경로와 검사 결과를 함께 알린다.
- 본 작업은 시작하지 않았음을 유지하고, 프롬프트 생성 이후의 실행을 임의로 이어가지 않는다.

## 요청 예시

다음 요청에는 이 스킬을 사용한다.

- “결제 취소 기능을 구현할 Codex 프롬프트를 만들어 줘.”
- “운영 장애를 조사하는 Agent 작업 지시서와 평가 기준을 작성해 줘.”
- “매주 보고서를 만드는 자동화 작업용 메타 프롬프트를 설계해 줘.”
- “이 요구사항으로 문서 작성 Agent가 실행할 Markdown 프롬프트를 만들어 줘.”

다음 요청에는 사용하지 않는다.

- “결제 취소 기능을 구현해 줘.”
- “이 기존 프롬프트를 더 좋게 고쳐 줘.”
- “확정한 구현 계획이 실제로 가능한지 검증해 줘.”
