# 전역 에이전트 지침

## 한국어 문서 작성

다음 작업에만 이 지침을 적용한다.

- 한국어로 사람 대상 문서를 새로 작성할 때
- 기존 한국어 사람 대상 문서를 수정하거나 재작성할 때
- 한국어 사람 대상 문서의 가독성과 구조를 검토할 때

일반 대화, 코드 자체의 작성·수정, 사람 대상 문서가 아닌 단순 결과 응답, 영어 또는 한국어가 아닌 문서에는 적용하지 않는다.

적용 대상이면 먼저 저장소의 문서 규칙·템플릿과 대상 문서의 구조를 확인한다. `$HOME/.agents/references/write-docs.md`는 새 한국어 사람 대상 문서를 작성하거나, 기존 문서의 구조·가독성 기준이 불명확할 때 읽고 적용한다. 규칙은 사용자 지시, 조직·저장소 템플릿과 용어, 함께 적용되는 전문 스킬, 상세 문서 지침 순으로 우선한다.

Markdown 문서를 작성하거나 수정했다면 다음 독립 검사기를 실행한다. 개발 역할에서는 아래의 로컬 실행 규칙에 따라 사용자에게 실행을 안내하고 결과 보고를 기록한다.

```bash
python3 "$HOME/.agents/scripts/validate_docs.py" <markdown-file-or-directory> [...]
```

## 세션 역할

- 사용자가 `역할: 기획`, `역할: 개발` 또는 현재 채팅의 역할을 지정하는 명시적인 요청을 하면 해당 명세를 읽고 현재 메인 에이전트에 적용한다. 관련 질문만으로 역할을 자동 선택하지 않는다.
- 역할 시작 시 아래 디렉터리의 role.md, persistence.md, files.md를 모두 읽는다.

| 역할 | 명세 디렉터리 |
|---|---|
| 기획 | `$HOME/.agents/references/planning/` |
| 개발 | `$HOME/.agents/references/development/` |

- 선택된 역할은 사용자가 명시적으로 변경하거나 해제할 때까지 현재 채팅에서 유지한다. 역할명·목표·저장 위치를 짧게 알리고 후속 메시지마다 선택을 다시 요구하지 않는다.
- 역할 선택만으로 하위 에이전트를 생성하지 않는다. 다른 채팅의 역할·진행 상태를 추정하지 않는다.
- 역할 변경 시 기존 작업의 결정·진행 상태·인계 사항을 디스크에 남긴다. 새 역할을 추정해 적용하지 않는다.
- 역할이 지정되지 않은 일반 대화에 역할 선택이나 산출물 디렉터리 생성을 요구하지 않는다.
- 기존 승인 절차와 프로젝트·레포의 적용 가능한 지침을 함께 따른다. 역할 선택이나 로컬 기록 생성을 외부 서비스 변경·제품 코드 수정의 승인으로 간주하지 않는다.

## 개발 역할의 로컬 실행

- 테스트·빌드·앱 실행 등 로컬 실행은 사용자가 결정하고 수행한다. 에이전트가 대신 실행하지 않는다.
- 에이전트는 필요한 실행·이유·영향·판단 기준을 제시하고, 사용자 완료 보고를 근거로 기록한다. 별도 재실행이나 증빙 제출을 완료 처리의 조건으로 요구하지 않는다.
- 코드·문서의 작성과 읽기 전용 조사는 승인된 개발 역할 범위에서 진행한다. 실제 실행과 결과 확인을 대신 수행했다고 보고하지 않는다.
