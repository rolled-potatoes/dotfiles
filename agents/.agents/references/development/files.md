# 개발 파일별 작성 규칙

각 파일이 답할 질문을 분리하고 문제·작업·결정·코드·검증을 연결한다. 작업 히스토리는 큰 단위로 남기며 필요할 때 세밀하게 조정한다. 시각 표기는 persistence.md의 KST 규칙을 따른다.

## session.md — 어떤 작업이며 어디까지 했는가

- 제목·역할·생성일, 기록용 ID와 확인 가능한 실제 세션 ID
- 간략한 현재 상태, 미결 사항과 다음 작업
- scope·progress·결정·검증·외부 활동·선행 세션 링크
- 마지막 갱신 시각

진입점으로만 사용하고 다른 파일의 본문과 긴 시계열 이력을 복사하지 않는다.

## scope.md — 무엇을 어떤 기준으로 구현하는가

- 해결할 문제 정의
- 포함 범위와 범위가 아닌 것
- 달성 조건: 목표·인수조건
- 전달된 스펙·방향글의 위치와 적용 기준
- 관련 티켓·레포와 작업 시작 시 확인한 코드 기준
- 구현할 큰 작업 단위와 남은 확인 사항

인수조건은 검증에 연결해 식별할 수 있게 한다. 원본 문서의 ID를 우선 재사용하고 필요하면 AC-001 같은 ID를 부여한다. 입력의 근거·현재 확정 내용·해석과 변경 제안을 구분한다. 변경 이력은 decisions에 연결한다.

## progress.md — 어떤 큰 작업을 수행했고 결과는 무엇인가

Jira 에픽 아래 스토리·작업을 나누는 정도의 큰 단위별로 다음을 남긴다. 실제 Jira 변경을 의미하지 않는다.

- 목적과 현재 상태
- 수행한 작업과 결과
- 관련 코드·결정·검증 링크
- 남은 일과 막힌 이유
- 순서가 중요한 시작·완료·중단·재개 시각

셸 명령·파일 수정·테스트 하나마다 항목을 추가하지 않는다. 큰 단위만으로 재개가 어렵거나 원인 이해가 부족한 부분만 상세화한다. 사용자 실행을 기다리는 상태와 코드 수정 중인 상태를 구분한다.

## decisions.md — 구현 중 무엇을 왜 선택했는가

- 식별 가능한 결정 ID, 질문과 출발점
- 대안·근거·선택 이유와 미채택 이유
- 구현상 선택인지 사용자 확인이 필요한 기획·동작 변경인지 구분
- 확정·제안·보류·대체됨 등 실제 판단 상태와 사용자 확인 근거
- 관련 인수조건·작업 단위·코드·검증과 반영 위치
- 확정·변경·번복 시각 및 이전 결정

의미 있는 판단이 생겼을 때 작성한다. 코드 편집마다 결정 항목을 만들지 않는다. 파일 저장·에이전트 권고·침묵을 사용자 승인으로 간주하지 않는다.

## verification.md — 어떻게 완료를 판단하며 결과는 무엇인가

착수 전 사용자와 검증 방법을 논의하고, 계획과 사용자 수행 보고를 같은 검증 항목에 연결한다.

| 구분 | 기록 내용 |
|---|---|
| 계획 | 연결된 인수조건, 검증 대상·수단, 필요한 환경·전제, 통과 기준 |
| 결과 | 사용자 완료 보고, 보고한 수행 방법·환경·결과, 제공된 증거 |
| 후속 조치 | 보고된 실패·미충족 원인, 수정과 사용자 재검증 결과 |

- 자동 테스트·수동 확인·시각 확인을 일괄 필수화하지 않는다. 작업에 맞는 수단을 먼저 논의한다.
- 테스트·빌드·앱 실행 등은 사용자가 결정하고 수행한다. 에이전트는 실행·목적·영향·판단 기준을 제시하고 보고를 기다린다.
- 사용자 완료 보고만으로 수행 완료를 기록한다. 별도 증빙·에이전트 재실행을 완료 처리 조건으로 요구하지 않는다.
- 사용자가 결과를 알려주면 그 보고에 따라 통과·실패 등을 기록한다. 완료만 보고하면 사용자 수행 완료로 남기며, 제공되지 않은 통과 결과·증거·실제 수행 시각을 추정하지 않는다.
- 실제 수행 시각이 제공되면 수행 시각으로, 아니면 완료 보고 시각으로 구분한다. 검증 계획 합의·변경과 재검증 보고도 시간을 기록한다.
- 검증 기준 변경은 이유를 남긴다. 중요한 통과 기준·인수조건 변경은 사용자 확인을 거친다.
- 미수행을 통과로 기록하지 않는다. 사용자 통과 보고 뒤 새 변경·실패·미해결 우려가 없다면 반복 실행을 요청하지 않는다.

## external-actions.md — 어떤 리스크와 코드 외 활동이 남았는가

리스크나 외부 활동이 필요한 경우에만 생성한다. 예: 스키마 마이그레이션, 환경변수 추가, 인프라 구축.

- 관련 작업·결정·변경과 연결된 필요 이유
- 리스크·예상 영향·확인된 제약과 불확실성
- 필요한 활동과 선행 조건
- 수행·확인 상태, 완료·검증·인계에 미치는 영향
- 사용자 결정·수행 완료 보고와 순서가 중요한 상태 변화 시각

리스크 자체와 필요한 행동을 구분한다. 담당자·일정·실행 순서는 확인됐을 때 기록한다. 환경변수는 이름·용도·설정 대상 등을 적고 실제 비밀값을 문서에 복사하지 않는다.

필요한 행동·이유·영향을 제시해 사용자에게 결정을 요청하고, 사용자 수행·완료 보고를 근거로 갱신한다. 문서에 적었다는 이유로 외부 서비스·환경을 변경하지 않는다. 테스트 같은 일상적인 검증 항목은 verification에 두고 중복 기록하지 않는다.
