# 개발 기록 저장·재개 규칙

개발 기록은 현재 Codex 프로젝트 루트의 세션별 디렉터리에 저장한다. 세션 기준 문서·과정 산출물·사용자 확인용 리포트를 구분하며, 재개할 때 기준 문서를 먼저 읽는다.

## 저장 위치와 소유 범위

```text
{프로젝트 루트}/
├── AGENTS.md
├── specs/
└── development/
    └── {생성일_주제_고유ID}/
        ├── session.md
        ├── scope.md
        ├── progress.md
        ├── decisions.md
        ├── verification.md
        ├── external-actions.md
        ├── artifacts/                # 선택: 과정 산출물, 필요하면 작업별 하위 폴더
        └── reports/                  # 사용자 확인용 리포트를 파일로 제공할 때
```

- 코드는 관련 저장소에 두고, `development/`에는 작업의 이해·재개·검증·인계에 필요한 기록을 둔다.
- 저장 규칙은 전역 개발 명세에서 관리하며, 프로젝트 AGENTS.md에 복제하도록 요구하지 않는다.
- 프로젝트 AGENTS.md에는 고유 작업 규칙·도메인 지식을 둔다. 세션 조사·진행·결정·결과를 자동 누적하지 않는다.
- 파일·디렉터리는 기록할 내용이 생길 때 만든다. 결정이 없으면 decisions.md를, 위험·외부 작업이 없으면 external-actions.md를 만들지 않는다.
- 세션 루트에는 기준 문서를 두고, 추가 과정 자료는 artifacts/, 사용자 확인용 리포트는 reports/로 구분한다. 문서별 책임은 files.md를 따른다.
- artifacts/와 reports/는 필요할 때 만든다. 조사·도식 등 과정 산출물은 선택 사항이며, experiments 영역은 이 명세에서 다루지 않는다.

## 세션 식별과 인계

- 이름은 `생성일_주제_고유ID`로 정한다. 예: `2026-10-24_회원초대-구현_e5f6g7h8`.
- 날짜는 작업 시작일, 주제는 작업을 식별하는 짧은 이름이다. 주제가 구체화돼도 디렉터리는 기본적으로 유지하고 문서 제목을 갱신한다.
- 실제 Codex 세션 ID를 확인하면 사용하고 전체 ID를 session.md에 남긴다. 확인할 수 없으면 별도 기록용 ID를 만들고 실제 세션 ID와 구분한다.
- 디렉터리명에는 짧은 ID를 쓴다. 경로가 겹치면 ID를 늘리거나 새로 만들며, 이름만으로 기존 세션을 이어받지 않는다.
- 같은 채팅은 기존 디렉터리에서 재개한다. 새 채팅은 기본적으로 새 디렉터리를 만들고, 인계받은 현재 상태·남은 작업을 기준 문서에 정리한다.
- 선행 세션의 문서 경로·인계 시점을 남기고, 확인 가능한 대화 딥링크를 함께 연결한다. 딥링크만으로 인계 내용을 대신하지 않는다.
- 다른 세션의 기록·산출물은 원래 위치에서 참조하고, 수정 제안과 새 판단은 자기 세션에 남긴다.
- 사용자가 기존 디렉터리를 이어 쓰도록 지정하면 해당 지시를 따른다. session.md에 현재 세션 식별자·인계 시점·이어 쓰는 근거를 남기고 기존 기록을 보존한다. 다른 활성 세션과 같은 파일을 동시에 갱신하지 않는다.
- 전달된 명세·방향성 문서와 관련 저장소의 작업 기준을 확인한다. 인계 시 참조 경로와 커밋·문서 버전 또는 인계 시점 사본으로 입력 기준을 남긴다.

## 신뢰와 저장

- session.md에서 범위·진행·결정·검증·남은 외부 작업으로 이동해 읽고 재개한다.
- 새 사용자 지시와 기록이 다르면 차이를 밝히고 명시적 정정·승인 범위에 맞춰 갱신한다. 오래된 기록보다 새 지시를 우선한다.
- 로컬 기록과 승인 상태를 구분한다. 승인된 티켓·공유 문서와 초안의 차이를 명시한다.
- 입력·범위·인수조건, 큰 작업의 진행·결과, 주요 결정, 검증 계획·보고, 위험·외부 작업이 바뀌면 기록한다. 중간 저장 요청·종료·인계 때도 갱신한다.
- 결정 번복과 계획 변경은 이전 판단·변경 이유를 연결한다. 다른 파일의 본문은 복제하지 않고 근거·반영 위치로 연결한다.
- 일반 대화나 명령마다 일지를 추가하지 않는다. 재개에 필요한 부분만 상세화한다.
- 저장 후 내용을 다시 읽고 저장 완료를 알린다. 문서 확인을 테스트·빌드·앱 실행 결과로 보고하지 않는다.

## 기존 자료 정리

- 기존 파일은 이름이 아닌 용도로 분류한다. 기준 문서에 남길 현재 내용과 별도 보존할 당시 자료를 구분한다.
- 기존 파일 재배치는 지침 개정과 별도로 범위를 정한다. 이동 전 문서 링크·도구 입력 경로·세션 간 참조를 확인하고, 이동 후 연결을 검증한다.
- 분류를 맞추기 위해 기존 기록을 삭제하거나 과거 자료를 현재 결과처럼 다시 쓰지 않는다.

## 시계열 기록

- 시각은 KST 기준 `YYYY-MM-DD HH:mm`의 24시간제로 적는다. 값에 타임존이나 오프셋을 붙이지 않는다.
- 사용자가 실제 수행 시각을 제공하면 수행 시각으로 기록한다. 완료 보고만 있으면 완료 보고 시각으로 구분한다. 모르는 과거 시각을 추정하지 않는다.
- 일반 설명이나 코드·도식·결과물의 개별 수정에는 순서가 중요할 때만 시각을 붙인다. 그 외에는 관련 작업·결정 기록으로 연결한다.

| 파일 | 시각을 기록할 대상 |
|---|---|
| progress.md | 큰 작업의 시작·완료·중단·재개 등 순서가 중요한 변화 |
| decisions.md | 주요 결정의 확정·변경·번복 |
| verification.md | 검증 계획 합의·변경, 사용자 결과·재검증 보고 |
| external-actions.md | 사용자 결정·완료 보고, 순서가 중요한 활동의 상태 변화 |
| session.md | 마지막 갱신 시각만 기록하고 상세 이력은 각 파일에 둠 |
| scope.md | 현재 기준을 유지하고 변경 이력은 decisions.md로 연결 |
