# 개발 영속화 규칙

개발 기록은 현재 Codex 프로젝트 루트 아래의 세션별 디렉터리에 저장한다. 기획과 합의한 세션 식별·격리·디스크 우선 원칙을 개발에도 적용한다.

## 저장 위치와 소유 범위

```text
{프로젝트 루트}/
├── AGENTS.md
├── specs/
└── development/
    └── {생성일_주제_고유ID}/
        ├── session.md
        ├── scope.md
        ├── progress.md
        ├── decisions.md
        ├── verification.md
        └── external-actions.md       # 필요할 때만 생성
```

- 코드는 관련 레포에 둔다. development/에는 작업을 이해하고 재개·검증·인계하는 기록을 둔다.
- 저장 규칙은 글로벌 개발 명세에서 적용한다. 프로젝트마다 AGENTS.md에 복제하도록 요구하지 않는다.
- 프로젝트 AGENTS.md는 프로젝트 고유 작업 규칙·도메인 지식의 공간이다. 세션 조사·진행·결정·결과를 자동 누적하지 않는다.
- 필요한 시점에 파일·디렉터리를 만든다. 의미 있는 결정이 없으면 decisions.md를, 리스크·외부 작업이 없으면 external-actions.md를 형식상 생성하지 않는다.
- 관련 조사·도식은 필요할 때 추가할 수 있으나 기본 필수 파일로 늘리지 않는다. experiments 영역은 이번 명세 범위 밖이다.

## 세션 식별과 인계

- 이름은 `생성일_주제_고유ID`로 정한다. 예: `2026-10-24_회원초대-구현_e5f6g7h8`.
- 날짜는 작업 시작일이며, 주제는 사람이 작업을 식별하는 짧은 이름이다. 주제가 구체화돼도 디렉터리는 기본적으로 유지하고 문서 제목을 갱신한다.
- 실제 Codex 세션 ID를 확인할 수 있으면 활용하고 전체 ID를 session.md에 남긴다. 확인 불가하면 별도 기록 ID를 생성하며 실제 세션 ID와 구분한다.
- 짧은 ID로 만든 경로가 이미 있으면 식별자를 늘리거나 새 ID를 생성한다. 우연히 이름이 같다는 이유로 이어받지 않는다.
- 같은 채팅 재개는 기존 디렉터리를 사용한다. 새 채팅에서 이어갈 때는 새 디렉터리를 만들고 선행 세션·인계 기준을 연결한다.
- 다른 세션의 기획·개발 기록은 읽기만 한다. 수정 제안과 새 판단은 자기 세션에 남긴다.
- 전달된 스펙·방향글과 관련 레포의 작업 기준을 식별한다. 인계 시 참조 경로와 커밋·문서 버전 또는 인계 시점 사본으로 입력 기준을 남긴다.

## 신뢰와 저장

- 대화 기억보다 저장 기록을 지속적인 기준으로 삼는다. 재개 시 session에서 scope·progress·결정·검증·남은 외부 작업을 확인한다.
- 새 사용자 지시와 저장 기록이 충돌하면 차이를 드러내고 명시적 정정·승인 범위에 맞춰 갱신한다. 오래된 파일을 이유로 새 지시를 무시하지 않는다.
- 로컬 기록과 승인 상태를 구분한다. 승인된 티켓·공유 문서와 초안의 차이를 명시한다.
- 입력·범위·인수조건 변경, 큰 작업의 진행 변화·결과, 중요한 결정, 검증 계획·사용자 보고, 리스크·외부 작업 변화, 중간 저장·종료·인계 때 관련 기록을 갱신한다.
- 결정 번복과 계획 변경은 이전 판단·이유를 연결한다. 다른 파일의 본문을 복제하기보다 근거·반영 위치로 연결한다.
- 일반 대화나 명령 하나마다 작업 일지를 추가하지 않는다. 큰 단위로 문맥이 부족한 경우만 상세화한다.
- 실제로 저장한 내용을 확인하고 완료를 알린다. 테스트·빌드·앱 실행으로 확인한 것처럼 보고하지 않는다.

## 시계열 기록

- 시각은 KST 기준 `YYYY-MM-DD HH:mm`의 24시간제로 적는다. 값에 타임존이나 오프셋을 붙이지 않는다.
- progress: 큰 작업의 시작·완료·중단·재개 등 선후관계가 중요한 변화.
- decisions: 주요 결정의 확정·변경·번복.
- verification: 검증 계획 합의·변경과 사용자 결과·재검증 보고.
- external-actions: 사용자 결정·완료 보고와 순서가 중요한 활동의 상태 변화.
- session: 마지막 갱신 시각만 기록하고 시계열 본문은 각 파일에 둔다. scope: 현재 기준을 유지하고 변경 이력은 decisions로 연결한다.
- 사용자가 실제 수행 시각을 제공하면 수행 시각으로 기록한다. 완료 보고만 있으면 완료 보고 시각으로 구분한다. 모르는 과거 시각을 추정하지 않는다.
- 순서가 중요하지 않은 일반 설명, 코드·도식·최종 결과물의 개별 수정마다 시간을 붙이지 않는다. 관련 작업·결정 기록으로 연결한다.
