# 기획 파일별 작성 규칙

각 사실과 결정의 본문을 맡을 파일을 구분하고, 다른 파일에서는 링크로 연결한다. 반복 질문과 조사를 줄이면서 사람이 읽고 공유할 수 있는 기록을 남긴다.

## session.md — 현재 작업은 무엇이며 어디까지 했는가

- 작업 제목·역할·생성일, 기록용 ID와 확인 가능한 실제 세션 ID
- 현재 상태, 미결 사항과 다음 작업의 짧은 요약
- brief, 조사·결정·도식·결과물과 선행 세션으로 가는 상대 링크

진입점과 간략한 작업 기록으로만 사용한다. 긴 논의 이력이나 다른 문서 본문을 복사하지 않는다.

## brief.md — 어떤 문제를 어느 범위에서 해결하는가

- 문제 정의: 상황, 문제, 배경과 목표
- 포함 범위와 제외 범위
- 인수조건: 달성 여부를 판단할 관찰·검증 기준
- 요구사항·관련 링크와 조직·팀·개인의 제약·전제
- 기대 결과물, 미확인 질문과 이후 변경의 결정 ID

초기 입력과 이후 합의를 구분한다. 빈 항목을 추정으로 확정하지 않는다. 초기 아이디어를 요구사항으로 자동 편입하거나 아이디어 목록을 brief에 누적하지 않는다. 아이디어가 문제·범위·인수조건 변경으로 확정되면 그 변경만 결정과 연결해 반영한다.

## research/{주제}.md — 무엇을 왜 조사했는가

조사는 주제별 문서로 남긴다. 초기 아이디어와 추가로 수집한 아이디어는 관련 조사 문서에서 함께 다룬다. 독립적인 아이디어 목록의 필요가 드러나기 전에는 별도 파일을 의무화하지 않는다.

- 조사 대상·질문·아이디어
- 조사 이유와 연결된 문제·논의
- 자료 제목·링크 또는 코드 경로
- 다시 찾고 공유할 수 있는 간결한 조사 요약

판단의 근거로 사용하면 사실과 해석, 가설을 구분하고 적용 한계를 남긴다. 유효성·재현에 필요하면 확인일, 버전·커밋을 기록한다. 링크만 나열하거나 모든 조사에 긴 보고서 목차를 강제하지 않는다.

## decisions.md — 어디서 시작한 판단이 어디에 반영됐는가

각 판단에 D-001 같은 ID를 부여하고 다음 내용을 기록한다.

- 질문과 출발점: 문제·요구사항·사용자 입력 요약·조사 질문의 기록 위치
- 후보 대안, 비교 기준, 근거가 연결된 장단점
- 채택·미채택·보류 내용과 그 이유
- 제안·확정·보류·대체됨 상태와 사용자 확정 근거
- 관련 brief 항목, 조사 문서, 도형·흐름, 결과물의 반영 위치
- 재검토 조건과 변경 시 이전 결정 ID

사용자 입력이 출발점이면 요지를 디스크에 보존한 뒤 연결한다. 결과물이 아직 없으면 반영 예정으로 표시하고 생성 후 실제 위치를 연결한다. 도식·결과물에서도 해당 결정 ID로 돌아갈 수 있게 한다. 모든 결정을 하나의 정해진 경로로 강제하지 말고 실제 근거와 반영 위치를 연결한다.

## diagrams/ — 함께 수정하는 구조·흐름·관계는 무엇인가

- 기본 편집 도구는 draw.io Desktop이며, `.drawio` 파일을 지속 원본으로 삼는다.
- 파일명은 대상과 목적을 식별하게 정한다. 예: `회원초대_권한검사-흐름.drawio`.
- 플로우차트·그래프·시퀀스 등 설명 대상에 적합한 형태를 선택한다.
- 같은 모델은 기존 원본을 발전시키고, 비교할 대안이 있으면 구분해 보관한다.
- 도형 ID와 지칭 가능한 라벨을 유지한다. 현재·제안 구조와 사실·가설·확정을 구분한다.
- 변경 이유와 관련 조사·결정을 텍스트 기록에 연결한다. 최종 결과물의 도식은 인계 기준 버전을 식별한다.
- 미리보기는 보조 자료다. 편집 원본을 함께 보존한다.

사용자와 에이전트는 순차 편집한다. 사용자 편집·저장 후 에이전트가 최신 파일을 다시 읽고, 사용자 도형·배치·연결을 보존하며 필요한 부분만 수정한다. 수정 후 Desktop의 외부 변경 알림에서 동기화한다.

동시수정은 피한다. 같은 속성 충돌의 안전한 병합을 가정하지 않는다. 임시 복구본이 나타나면 디스크 원본과 차이를 확인하고 사용자 변경을 임의로 잃지 않게 한다. 실제 사용에서 반복적인 불편·요구사항 미충족이 드러나면 도구를 재검토한다.

## deliverables/ — 어떤 결과물을 전달할 것인가

- 축적한 문제 맥락·근거·결정을 바탕으로 사용자가 요청한 목적과 형식에 맞춰 작성한다.
- Markdown과 편집 가능한 도식 등 복수 파일로 구성할 수 있다.
- 근거·결정과 연결하되 공통 필수 항목이나 고정 목차를 강제하지 않는다.
- 사용자 승인 전 결과물을 승인 완료로 표시하지 않는다.
- 사용 경험에서 지향하는 형식이 드러나면 사용자와 논의해 반영한다.
