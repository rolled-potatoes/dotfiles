# 기획 파일별 작성 규칙

기획 문서와 산출물은 전역 writing style을 따른다. 사실과 결정은 담당 파일에 한 번만 쓰고, 다른 파일에서는 링크로 연결한다.

## session.md — 현재 작업은 무엇이며 어디까지 했는가

- 작업 제목·역할·생성일, 기록용 ID와 확인 가능한 실제 세션 ID
- 현재 상태, 미결 사항과 다음 작업의 짧은 요약
- brief.md·조사·결정·도식·결과물·선행 세션으로 가는 상대 링크

작업의 진입점으로 사용하며, 긴 논의 이력이나 다른 문서 본문은 복사하지 않는다.

## brief.md — 어떤 문제를 어느 범위에서 해결하는가

- 문제 정의: 상황, 문제, 배경과 목표
- 포함 범위와 제외 범위
- 인수조건: 달성 여부를 판단할 관찰·검증 기준
- 요구사항·관련 링크와 조직·팀·개인의 제약·전제
- 기대 결과물, 미확인 질문과 이후 변경의 결정 ID

초기 입력과 이후 합의를 구분하고, 빈 항목은 추정으로 확정하지 않는다. 아이디어는 조사 문서에 두고, 문제·범위·인수조건 변경으로 확정된 내용만 결정과 연결해 반영한다.

## research/{주제}.md — 무엇을 왜 조사했는가

조사와 아이디어는 주제별 문서에 함께 정리한다. 별도 아이디어 목록은 필요할 때만 만든다.

- 조사 결론과 간결한 요약
- 조사 대상·질문·아이디어
- 조사 이유와 연결된 문제·논의
- 자료 제목·링크 또는 코드 경로

판단 근거는 사실·해석·가설을 구분하고 적용 한계를 남긴다. 유효성·재현에 필요한 확인일·버전·커밋을 기록한다. 링크만 나열하거나 긴 보고서 목차를 강제하지 않는다.

## decisions.md — 어디서 시작한 판단이 어디에 반영됐는가

각 판단에 `D-001` 같은 ID를 부여하고 다음 내용을 기록한다.

- 채택·미채택·보류 내용과 이유, 제안·확정·보류·대체됨 상태
- 판단의 출발점인 문제·요구사항·사용자 입력·조사 질문의 기록 위치
- 후보 대안, 비교 기준, 근거가 연결된 장단점
- 사용자 확정 근거
- 관련 brief.md 항목·조사 문서·도형·흐름·결과물의 반영 위치
- 재검토 조건과 변경 시 이전 결정 ID

사용자 입력이 판단의 출발점이면 요지를 저장해 연결한다. 결정마다 실제 근거와 반영 위치를 연결하고, 도식·결과물에서도 결정 ID로 돌아갈 수 있게 한다. 아직 없는 결과물은 반영 예정으로 표시한 뒤 생성 시 링크를 갱신한다.

## diagrams/ — 함께 수정하는 구조·흐름·관계는 무엇인가

- 기본 편집 도구는 draw.io Desktop이며, `.drawio` 파일을 원본으로 보존한다.
- 파일명은 대상과 목적을 식별하게 정한다. 예: `회원초대_권한검사-흐름.drawio`.
- 플로우차트·그래프·시퀀스 등 설명 대상에 적합한 형태를 선택한다.
- 구조·관계·흐름을 빠르게 파악하도록 도형과 연결선에는 핵심 명칭·역할·관계만 간결하게 표현한다.
- 보충 내용은 도형 밖의 짧은 메모로 남기고, 상세 설명·조건·근거는 문서로 링크한다. 도형 안에 긴 설명을 나열하지 않는다.
- 같은 모델은 기존 원본을 발전시키고, 비교할 대안이 있으면 구분해 보관한다.
- 도형 ID와 식별 가능한 이름을 유지한다. 현재·제안 구조와 사실·가설·확정을 구분한다.
- 변경 이유를 관련 조사·결정 기록에 연결한다. 최종 도식에는 인계 기준 버전을 남긴다.
- 미리보기는 보조 자료이며, 편집 원본을 함께 보존한다.

사용자와 에이전트는 다음 순서로 편집한다.

1. 사용자가 편집하고 저장한다.
2. 에이전트가 최신 파일을 다시 읽고, 사용자 도형·배치·연결을 보존하며 필요한 부분만 수정한다.
3. draw.io Desktop의 외부 변경 알림에서 동기화한다.

동시 편집은 피하고, 같은 속성의 충돌을 안전하게 병합할 수 있다고 가정하지 않는다. 임시 복구본은 디스크 원본과 비교해 사용자 변경을 보존한다. 불편이나 요구사항 미충족이 반복되면 도구를 재검토한다.

## deliverables/ — 어떤 결과물을 전달할 것인가

- 문제 맥락·근거·결정을 바탕으로 요청한 목적과 형식에 맞춰 작성한다.
- Markdown과 편집 가능한 도식 등 복수 파일로 구성할 수 있다.
- 근거·결정을 연결한다. 공통 필수 항목이나 고정 목차는 강제하지 않는다.
- 사용자 승인 전 결과물을 승인 완료로 표시하지 않는다.
- 사용 중 필요한 형식이 드러나면 사용자와 논의해 반영한다.
