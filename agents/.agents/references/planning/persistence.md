# 기획 기록 저장·재개 규칙

기획 기록은 세션별 디렉터리에 저장하고, 재개할 때 디스크 기록을 먼저 읽는다. 파일별 내용은 files.md를 따른다.

## 저장 위치

- 현재 Codex 프로젝트의 기준 디렉터리를 프로젝트 루트로 사용한다.
- 기획 세션은 `{프로젝트 루트}/specs/{생성일_주제_고유ID}/`에 둔다.
- 진입 기록은 세션 루트의 `session.md`에, 기획 자료는 `planning/`에 둔다.
- 파일·디렉터리는 기록할 내용이 생길 때 만든다. 빈 파일을 일괄 생성하지 않는다.
- 이 규칙은 전역 기획 명세에서 관리하며, 프로젝트 AGENTS.md에 복제하도록 요구하지 않는다.
- 프로젝트 AGENTS.md에는 프로젝트 고유의 작업 규칙·도메인 지식을 둔다. 세션의 조사·진행·결정·결과물을 자동 누적하지 않는다.
- 프로젝트 공통 지식으로 반영할 내용은 세션 원본·근거를 유지하고 별도 변경안으로 제시한다.

```text
{프로젝트 루트}/
├── AGENTS.md
├── specs/
│   └── {생성일_주제_고유ID}/
│       ├── session.md
│       └── planning/
│           ├── brief.md
│           ├── research/
│           ├── decisions.md
│           ├── diagrams/
│           └── deliverables/
└── development/                  # 개발 기록 위치; 상세 명세는 별도
```

## 세션 식별과 소유 범위

- 이름은 `생성일_주제_고유ID`로 정한다. 예: `2026-10-23_회원초대-정책정의_a1b2c3d4`.
- 생성일은 작업 시작일, 주제는 내용을 식별하는 짧은 이름이다.
- 실제 Codex 세션 ID를 확인하면 사용하고 전체 ID를 session.md에 남긴다. 확인할 수 없으면 별도 기록용 ID를 만들고 실제 세션 ID와 구분한다.
- 디렉터리명에는 짧은 ID를 쓴다. 경로가 겹치면 ID를 늘리거나 새로 만들며, 이름만으로 기존 세션을 이어받지 않는다.
- 주제가 구체화돼도 디렉터리는 기본적으로 유지하고 문서 제목을 갱신한다.
- 같은 채팅은 기존 디렉터리에서 재개한다. 새 채팅은 새 디렉터리를 만들고 선행 세션·인계 시점을 연결한다.
- 다른 세션의 기록은 읽기만 한다. 수정 제안과 새 판단은 자기 세션에 남긴다.
- 여러 세션이 상태 파일 하나를 덮어쓰는 구조는 기본으로 두지 않는다.

## 신뢰와 재개

- session.md에서 관련 brief.md·근거·결정·도식으로 이동해 읽고 재개한다.
- 새 사용자 지시와 기록이 다르면 차이를 밝히고 명시적 정정·승인 범위에 맞춰 갱신한다. 오래된 기록보다 새 지시를 우선한다.
- 로컬 기록과 승인 상태를 구분한다. 승인된 티켓·공유 문서와 초안의 충돌을 명시한다.
- 결정은 대화 기억만으로 바꾸지 않는다. 번복 시 이전 결정과 변경 이유를 연결한다.
- 후속 세션·개발에 인계할 때 참조 경로와 커밋·문서 버전 또는 인계 시점 사본으로 입력 기준을 남긴다.

## 저장 시점

- 목표·배경·요구사항·제약·범위가 추가되거나 바뀌었을 때
- 판단에 영향을 주는 조사 결과를 확보했을 때
- 대안의 채택·기각·보류, 확정 결정의 변경이 생겼을 때
- 도식을 수정했을 때
- 중간 저장 요청, 작업 종료와 인계 시점

기록할 내용이 없는 일반 대화에서는 파일을 갱신하지 않는다. 저장 후 내용을 다시 읽고 저장 완료를 알린다.
