# 기획 영속화 규칙

기획 기록은 디스크를 기준으로 재개하고, 세션별 디렉터리에서 관리해 다른 세션과의 충돌을 피한다. 파일별 책임은 files.md를 따른다.

## 저장 위치

- 현재 Codex 프로젝트의 기준 디렉터리를 프로젝트 루트로 사용한다.
- 기획 세션은 `{프로젝트 루트}/specs/{세션 구분}/`에 둔다.
- 진입 기록은 세션 루트의 session.md에, 기획 자료는 planning/에 둔다.
- 필요한 디렉터리와 파일은 기록 시점에 생성한다. 형식만 맞추기 위한 빈 파일을 일괄 생성하지 않는다.
- 이 저장 규칙은 글로벌 기획 명세에서 적용한다. 프로젝트마다 AGENTS.md에 복제하도록 요구하지 않는다.
- 프로젝트 AGENTS.md에는 프로젝트 고유의 작업 규칙·도메인 지식을 둔다. 세션의 조사·진행·결정·결과물을 자동 누적하지 않는다.
- 프로젝트 공통 지식으로 반영할 내용이 생기면 세션 원본과 근거를 유지하고 별도 변경안을 제시한다.

```text
{프로젝트 루트}/
├── AGENTS.md
├── specs/
│   └── {생성일_주제_고유ID}/
│       ├── session.md
│       └── planning/
│           ├── brief.md
│           ├── research/
│           ├── decisions.md
│           ├── diagrams/
│           └── deliverables/
└── development/                  # 개발 기록 위치; 상세 명세는 별도
```

## 세션 식별과 소유 범위

- 이름은 `생성일_주제_고유ID`로 정한다. 예: `2026-10-23_회원초대-정책정의_a1b2c3d4`.
- 생성일은 작업 시작일, 주제는 내용을 식별하는 짧은 이름이다.
- 실제 Codex 세션 ID를 확인할 수 있으면 활용하고 전체 ID를 session.md에 남긴다. 확인 불가하면 기록용 ID를 별도로 생성하고 실제 세션 ID와 구분한다.
- 이름에는 짧은 ID를 사용하되 같은 경로가 존재하면 식별자를 늘리거나 새 ID를 생성한다. 우연히 이름이 같다는 이유로 기존 세션을 이어받지 않는다.
- 주제가 구체화돼도 디렉터리는 기본적으로 유지하고 문서 제목을 갱신한다.
- 같은 채팅 재개는 기존 디렉터리를 사용한다. 새 채팅에서 이어갈 때는 새 디렉터리를 생성하고 선행 세션과 인계 시점을 연결한다.
- 다른 세션의 기록은 읽기만 한다. 수정 제안과 새 판단은 자기 세션에 남긴다.
- 공유 상태 파일을 모든 세션이 함께 덮어쓰는 구조는 기본으로 두지 않는다.

## 신뢰와 재개

- 대화 기억보다 디스크 기록을 지속적인 작업 기준으로 삼는다. session.md에서 관련 brief·근거·결정·도식으로 이동해 읽고 이어간다.
- 새 사용자 입력이 저장 내용과 다르면 차이를 드러내고, 명시적 정정·승인 범위에 맞춰 기록을 갱신한다. 오래된 파일을 이유로 새 지시를 무시하지 않는다.
- 로컬 기록의 존재와 승인 상태를 구분한다. 승인된 티켓·공유 문서와 초안이 충돌하면 차이를 명시한다.
- 저장된 결정을 대화 기억만으로 조용히 바꾸지 않는다. 번복 시 이전 결정과 변경 이유를 연결한다.
- 후속 세션·개발에 인계할 때는 참조 경로와 함께 커밋·문서 버전 또는 인계 시점 사본으로 입력 기준을 식별한다.

## 저장 시점

- 목표·배경·요구사항·제약·범위가 추가되거나 바뀌었을 때
- 판단에 영향을 주는 조사 결과를 확보했을 때
- 대안의 채택·기각·보류, 확정 결정의 변경이 생겼을 때
- 도식을 수정했을 때
- 중간 저장 요청, 작업 종료와 인계 시점

기록할 내용이 없는 일반 대화마다 파일을 갱신하지 않는다. 저장 후 파일 내용을 다시 확인하고 저장 완료를 알린다.
